### 环境坑（重要）
在本机由 agent 的 Bash 执行 `git fetch` / `git update-ref` 时，命令返回 exit 0 并打印 "main -> origin/main" 已更新，
但 `.git` 内的 ref **实际不落盘**（远程跟踪 ref 全部集中在 `.git/packed-refs`，loose 目录被清空、写入被吞）。
结果：`origin/main` 长期卡在旧值 3a1f2c6，导致一切 ahead/behind 判断失真（一度误判远程 main 被 force-push 回退）。

应对：
1. 用 `git ls-remote origin` 取远程真实指向，不要只信本地 remote-tracking ref。
2. 需要修正时用 Edit 工具直接改 `.git/packed-refs`（文本写入有效，git 命令写入无效）。
3. **packed-refs 必须按 refname 排序**（不是按 hash）。顺序错会触发 `fsck: packedRefUnsorted`，
   进而让 `origin/main` 之类的 ref 整体无法解析（rev-parse 报 unknown revision）。

### 🚨 事故：commit 成功但分支 ref 消失
`git commit` 打印 `[feat/acceptance-overhaul bf123c6]` 成功，紧接着 `git log` 却报
`fatal: your current branch 'feat/acceptance-overhaul' does not have any commits yet`，
`git status` 变成 `No commits yet` + 全部文件显示为 `A`（索引被当作全新仓库）。

原因：`.git/refs/heads/feat/` 整个目录丢失（只剩 `main`），ref 写入被吞（与上方「环境坑」同一根因）。
**提交对象没丢** —— `git log bf123c6` 链完整，reflog（`logs/HEAD`）最后一行记录了 `ff20a9c → bf123c6`。

恢复：用 Write 工具直接写 `.git/refs/heads/feat/acceptance-overhaul` = `bf123c6...`（git 命令写入无效，文本写入有效）。
恢复后 `git log`/`status`/`worktree list` 全部正常。

**结论：本环境下任何改 ref 的 git 操作（commit/checkout/branch/reset）都可能静默损坏仓库。
建议 commit/push 这类操作放到用户自己的普通终端执行，agent 侧只做只读 + 文件级文本写入。**
